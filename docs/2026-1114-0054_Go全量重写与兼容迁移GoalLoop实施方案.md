## 1. 背景与目标

### 1.1 背景

当前 iAnchor 是 macOS CLI，通过将配置文件迁入 iCloud Drive、在原路径创建软链接，并在共享目录内记录 SQLite 元数据，实现跨 Mac 使用配置。现有 Node.js 发行依赖 Homebrew Node 与匹配 Node ABI 的 better-sqlite3 预编译模块。

用户决定用 Go 完整替换实现，保持现有功能与旧数据兼容，消除产品侧 Node.js 依赖。用户已明确批准若干异常行为的安全修复，不能把“完全一致”解释为复制这些已批准修复的缺陷，也不能借重写擅自优化其他行为。

### 1.2 目标

1. Go 成为唯一产品实现；保留 `ianchor` 命令、子命令、参数、交互、输出、退出码、补全及核心文件行为。
2. 原位使用现有本机配置、iCloud 目录、SQLite schema、记录与软链接，无需用户重新初始化或重新添加条目。
3. Go 1.27.0 为初始固定工具链，使用 `database/sql` 与 `modernc.org/sqlite`；产品构建 `CGO_ENABLED=0`。
4. 目标平台 macOS 13+，支持 `darwin/amd64` 与 `darwin/arm64`；保留 `puppetdevz/tap/ianchor` 的 Homebrew 安装入口，改为源码构建。
5. 完成获批安全差异、普通错误补偿、测试迁移、发布能力适配及受影响文档同步。
6. 全部自动门禁通过；用户于 2026-11-15 明确以“单元测试语句覆盖率 100%”替代人工验收，因此该覆盖率达标即视为验收通过。最终对抗式审查无遗留问题且取得用户提交授权后，才进行本地 Commit。

### 1.3 非目标与禁止事项

- 不增加 Linux/Windows 支持、后台服务、新命令、独立二进制发行渠道或新的同步后端。

- 不承诺多台 Mac 同时修改同一条目的冲突解决；人工同步验收采用前一设备操作关闭数据库、同步完成后再由下一设备操作的顺序。
- 不新增持久化跨进程操作日志，不承诺 `kill -9`、进程崩溃、系统崩溃或断电后的自动恢复和持久性。

## 4. 功能需求与兼容契约

### REQ-001：CLI 完整覆盖

根入口 `ianchor` 与下表接口必须保留；没有新增业务命令。

| 接口 | 参数与选项 |
| --- | --- |
| 根命令 | `-V, --version`；`-h, --help` |
| `init` | `--dir <name>` |
| `list` | `--json` |
| `add <source>` | `--name <name>`；`--force` |
| `recover <name>` | `--force` |
| `relink <name>` | 无额外业务选项 |
| `remove <name>` | `-y, --yes` |
| `help [command]` | 保留 Commander 当前帮助行为 |
| `__complete` | 隐藏；动态名称输出 |
| `completion [shell]` | 隐藏；默认 zsh，仅支持 zsh/bash |

各子命令保留帮助。必须从基线提取完整帮助 golden，覆盖无参数、缺参数、多余参数、未知命令/选项、拼写建议、选项值缺失、短/长选项、`--`、前导横线名称、帮助/版本优先级及 EOF/信号的可观察行为。不得用 Go 框架默认行为替代基线。

已核实代表性契约：无参数根帮助输出 stderr、退出 1；帮助退出 0；`-V` 输出 `1.1.1\n`，`-v` 不支持；`list --version` 仍输出版本；`--help --wat` 以帮助为先；`completion fish` 输出 `Unsupported shell: fish. Expected zsh or bash.`，没有 `Error:` 前缀。其余 parser 细节由基线测试冻结。

### REQ-002：交互、输出与终端

1. 业务错误通常为 stderr `Error: <message>\n`、退出 1；解析错误保留基线 `error:` 与具体文案。已批准安全拒绝可新增明确错误。
2. 保留 init 的目录问题、add 的一次前缀提问、remove 的 `[y/N]` 提示；删除仅接受 trim 后不区分大小写的单个 `y`，`yes` 也取消，取消退出 0。
3. init 交互空答案使用 `ianchor`，交互答案 trim；不要把显式 `--dir` 一律 trim。add 前缀 trim 后为空取消冲突处理，不能改为无限重问。
4. 成功文案、路径箭头、空列表提示、表头 `Name / Original Path / Type / Status`、Unicode 边框及 JSON 格式从基线冻结。
5. 保留颜色角色：成功绿、错误红、问题黄、表头青、辅助 dim。无色比较不等于可以删除颜色功能。
6. list spinner 保留 100ms 延迟、80ms 帧间隔、`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`、`Loading entries…` 及清理串 `\r\x1b[K`。当前即使非 TTY 或 `--json` 也可能写 stderr；未经批准不得擅自取消。
7. spinner 的调度常量可用可控时钟测试；实测不要求逐帧发生于相同墙钟时刻。正常完成、错误和退出必须停止计时并清理。

### REQ-003：路径与本机配置

沿用：

```text
iCloud base = <home>/Library/Mobile Documents/com~apple~CloudDocs
本机配置 = <home>/.config/ianchor.json
默认同步目录 = <iCloud base>/ianchor
共享数据库 = <同步目录>/ianchor.db
```

本机配置继续写 `{ "dirName": ... }` 的两空格缩进 JSON，末尾换行；保持既有默认和读取行为。除获批安全拒绝外，不擅自增加配置字段、迁移目录或改变恢复策略。

隔离 HOME 必须可用于自动测试。源路径允许来自用户指定的目录或其他卷，不新增“必须在 HOME 内”的限制。目标路径安全以规范化的 iCloud base/configDir 为锚点，识别路径边界和父目录链接，不能只做字符串前缀比较。

### REQ-004：旧 SQLite 原位兼容

保持表结构，不增加迁移、schema version、设备字段或 CHECK：

```sql
CREATE TABLE IF NOT EXISTS entries (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  original_path TEXT,
  type TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'linked',
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);
```

- 普通可写打开仍使用 WAL 并保证建表；只读打开要求库已存在，不初始化、不建表、不切换 journal 模式。
- 设置并测试与现有驱动一致的 5000ms busy timeout；这是基线值，不是新增性能 SLA。连接池不能使部分连接漏设 pragma。
- 普通新增/发现保留 `INSERT OR IGNORE` 语义；只有获批 force 接管场景执行明确更新。
- `SELECT * ORDER BY name` 排序、nullable 字段、SQLite UTC 时间字符串、硬删除和 status/updated_at 更新规则保持。
- `SELECT *` 必须是真正的列漂移透传：Go 用 `SELECT *` 读取列名与列序，再按 Node 行对象的语义输出（列名精确小写匹配、列序保持、JS 属性顺序把规范数组索引键前置、`Buffer` 为 `{"type":"Buffer","data":[...]}`、数字按 double 输出因此超出 2^53 舍入且 NaN/±Inf 变 `null`、` `/` ` 以字面量写出）。modernc 驱动会把声明为 `DATE`/`DATETIME`/`TIMESTAMP` 的列自动转成 `time.Time`，因此这些列用 `CASE WHEN 1 THEN "col" ELSE "col" END` 重查一次以取得原文本；`list` 的实时 `status` 与该命令对行的改写按 Node `{ ...entry, status }` 的语义处理（列集合缺 `status` 时追加在末尾）。
- 避免 DSN 对空格、`#`、`?`、Unicode 路径的错误解析；不得用未转义路径拼 URI 或用字符串拼接业务 SQL。
- Node→Go→Node 双向读写，核验主库、WAL 和关闭行为；不以新建空库测试替代旧库兼容。
- 不自动修复、删改或重新解释异常旧记录；涉及危险路径时安全拒绝并告知，不做静默清洗。

### REQ-005：init 与发现

仅扫描同步目录顶层；已有 DB 名称跳过；保持 `ianchor.db*`、`.DS_Store`、`Thumbs.db`、`.bak`、现有图片扩展名过滤及其对目录名也生效的事实。已知配置映射从基线完整迁移。

发现记录默认为 unlinked，未知路径为 null，不建链接。保留 add 默认只去掉一个前导点的命名规则，不顺手修正其与已知配置映射的差异。

### REQ-006：add 与获批 force 语义

正常 add 保留路径解析、默认名、自定义名、源软链接拒绝、前缀冲突和文件/目录处理。同卷优先 rename；EXDEV 路径需覆盖复制及后续源处置的等价语义。

获批 `--force` 例外：

1. 完整替换目标，不合并已有目录，不留下旧目标额外文件。
2. 已有同名记录保留 `id/created_at`，更新 `original_path/type/status/updated_at`；不能再因 `INSERT OR IGNORE` 静默保留旧元数据。
3. 换源时，仅清理原记录路径上 readlink 文本确实指向该同步目标的旧软链接；保留实体、无关链接和其他设备内容，不做全盘链接搜索。
4. 普通错误按 REQ-011 补偿；不得先不可逆删除旧目标，之后才尝试构造新目标。
5. 刚创建的新链接、更新的记录与目标内容必须对应；合法已存在实体不能被误判为可安全清理的旧管理链接。

### REQ-007：recover

保留：验证记录/云端内容/原路径；备份云端到 `.bak/<name>`，覆盖该条目的旧备份；本地有实体且无 force 则拒绝；force 才允许覆盖；复制到原位置；保留云端和共享记录，成功不擅自修改记录 status/updated_at。按 DELTA-014，无关的非悬空软链接也视为本地冲突，仅 `--force` 可替换并在普通失败时恢复。

特别保留现有测试规定：本地冲突报错之前也会产生/更新云端备份。因此不把“任何失败都零副作用”写成要求。force 当前并不为被覆盖的本地内容保留永久历史；不得擅自扩展为版本管理。临时补偿保护不等于改变正常成功后的单份备份语义。

### REQ-008：relink

正确指向目标时仍报 already linked，不改成幂等成功。原路径为实体时仍改名固定 `<originalPath>.bak`，不自行增加备份轮换。成功更新 status=linked。

获批修复悬空链接：使用不跟随链接的探测区分“路径不存在”和“链接目标不存在”，安全处理后重新链接，不产生基线 EEXIST 问题。不得借此扩大删除实体或无关路径的范围。本项最初仅批准 relink；后续用户另行批准 DELTA-008：recover 遇本地悬空链接时在写备份前拒绝，包括 `--force`。remove 等其他行为若发现同类问题，任何尚未获批的可观察差异仍须先提问，不得以“统一处理”为由扩大授权。

### REQ-009：remove 与 list

- remove 保留删除共享实体和 DB 记录的含义；只删除恰好指向该共享路径的本地链接；保留本地实体、无关链接和 `.bak`。
- list 继续实时推导 linked/unlinked/deleted，不把实时状态写回数据库；未知路径显示 `(unknown)`；deleted 提示保持 `deleted (use "ianchor remove" to clean up)`。
- 现有云端 access 失败显示 deleted 的规则保持，不擅自增加新状态；链接状态仍按 readlink 文本比较，不改成“解析后指向同 inode 即 linked”。
- JSON 保留所有 DB 字段、顺序、null、两空格缩进与末尾换行；不能因 Go 零值、省略空值或 map 随机顺序改变协议。

### REQ-010：获批路径安全

所有破坏性入口必须在操作前完成校验，至少覆盖：

- 空/特殊组件、绝对名称、目录分隔符、`..` 路径穿越、名称/前缀拼接后越界。
- 内部数据库及其 `ianchor.db*` 辅助文件、备份根 `.bak` 等内部命名碰撞，包含目标文件系统大小写行为。
- `--dir` 使同步目录逃出规范化 iCloud base，包括路径组件/父目录软链接造成的越界。
- 源就是目标、源目标互相包含、把同步根/内部库作为待迁移源等重叠风险。
- 旧 DB 中危险路径在使用时被拒绝；不自动改名、删除记录或迁移旧内容。

不得误拒绝正常带空格、冒号、Unicode、通配符字面量或前导横线的合法条目。补全读取旧名称是只读协议，仍按其原过滤规则输出，不能以清洗名称为由修改旧库。

### REQ-011：普通错误补偿

覆盖 add/force、recover、relink、remove 中能捕获的普通失败。用操作阶段、可逆暂存与 DB transaction 明确提交点，不能声称 SQLite transaction 能覆盖文件系统。

- 在不可逆处置前保留必要数据；同卷与跨卷分别设计恢复动作。跨卷 add 将源对象在源卷原地暂存至提交点，再清理该对象；提交前失败通过同卷重命名恢复，提交后清理失败须明确报告残留位置和可能的部分清理。
- 在提交点前失败，恢复操作前的源/目标/相关链接/记录；保留 REQ-007 明确批准的 recover 冲突备份副作用。
- 补偿本身失败时，不谎报成功或“已回滚”；保留仍可恢复的数据，返回明确失败并报告准确恢复位置与步骤，不能通过继续删除来清理现场。
- 明确逻辑提交后的暂存清理失败：报告已提交/清理失败的实际状态，保留可恢复内容，不伪称完整回滚；对应输出差异仅限获批失败安全边界并有测试。
- 需要暂存时采用每次操作独立的临时命名，云端暂存优先置于现有 init 会整体忽略的 `.bak` 子树；若源与 `.bak` 不在同卷，必须在源侧同卷暂存以保证原对象可回滚，并在清理失败时明确报告路径；跨卷源侧暂存采用唯一临时路径，绝不覆盖已有内容。
- 普通成功清理自身暂存，不删除未知或其他进程的暂存；不新增开机/下次运行自动扫尾协议。
- 不把上述机制包装成崩溃或断电安全，不修改共享 schema，不引入新的跨设备协调承诺。

### REQ-012：补全完整迁移

`__complete` 保持隐藏、只读、按 DB name 排序；原始名称以 NUL 分隔且末尾有 NUL；过滤 NUL/LF/CR；不按实时状态过滤；目录/库缺失及坏库时静默，不初始化用户配置或数据库。

`completion` 原样输出现有 Bash/zsh 脚本，默认 zsh，其他 shell 错误保持。推荐用 `go:embed` 保留脚本字节；不可替换为 Cobra 等框架默认补全。

迁移当前 shell 真正 Tab/PTY 和安全用例：Bash 3.2、zsh、空格、冒号、反斜杠、通配符、命令替换字面量、前导 `-`、`--`、flag/value 跳过、仅首个位置参数、目录 `/` 和不修改 `COMP_WORDBREAKS`。不得执行条目名称中的 shell 语句。

### REQ-013：Go 工程与测试替换

## 5. 技术方案与兼容判定

### 5.1 Oracle 与语言无关契约

1. 将固定 commit 导出至仓库外临时目录，保留必要源码/锁依赖供迁移验证，不用 checkout/reset 覆盖当前工作树。

4. 固化无色 golden、schema/data 夹具、shell 期望与白名单差异；最终 Go 测试不依赖产品 JS 实现。
5. 基线运行安装如有障碍，先复用已核实环境或依照锁依赖准备；不得换浮动依赖并把变化后的输出当原基线。

不全局 trim、不移除任意换行/字段、不忽略 JSON 顺序或重排表格。固定无色测试中不要以“终端差异”为由吞掉正常输出差异；颜色/PTY 用专门用例验证。

### 5.4 存储与文件层关键原则

- 对 DB transaction 与 filesystem commit 分别建模；配置文件、云端内容、原路径和备份都有自己的失败点。
- 使用 Lstat 判断路径自身，readlink 文本用于兼容状态判定；规范化路径仅用于安全边界，不改变用户可见路径协议。
- 明确源/目标的文件、目录、正常/悬空链接以及同卷/跨卷组合；按 Node 基线验证链接转换并按 DELTA-012 校验内容、结构、链接目标和普通权限。复制或校验失败保留原件，不虚构 ACL/xattr 或 iCloud 上传保证。
- driver/连接打开应实际验证可用性，处理只读 DSN 与池化 pragma；不要把 database/sql 的懒连接成功当打开成功。
- 不通过 immutable/read-uncommitted 等方式掩盖 WAL 或锁问题；旧版读写兼容要有真实证据。

## 9. Harness Goal Loop 执行指令

### 9.2 对抗式审查与修复循环

- 对所有变更内容开展**对抗式审查（Adversarial Review）**，覆盖代码、测试、补全脚本、版本来源、Formula、CI、发布辅助及文档，不能只审核心 Go 文件。
- 重点攻击：危险路径和父链接、同名接管、目录替换、悬空链接、可逆提交顺序、补偿失败、只读误写、WAL/锁兼容、JSON/终端协议、shell 注入、供应链与发布防降级。
- 若发现问题，必须基于**第一性原理**分析根因：写出被破坏的不变量、最小复现场景、失败机制、修复建议与影响范围；执行修复并补回归测试，不能仅压制错误或放宽断言。
- 修复后先跑相关测试，再跑完整自动 Gate；继续审查最新全部 diff，循环直至无遗留问题。优先用独立 reviewer；不可将“代理退出成功”当作“没有问题”，必须阅读结果。
- 期间若有疑问、需决策、发现新兼容差异或权限边界，优先调用 `grilling` 技能向用户提问；环境无该技能时如实告知并用结构化卡片澄清。

```text
选定契约 → 复现/测试 → 最小实施或修复 → 相关回归 → 全量自动验证
        → 对抗式审查 → 有问题则第一性原理分析并回到修复
        → 自动全绿且无问题 → 等用户人工验收
        → 人工失败则复现并修复/回归/重审，必要时重做受影响人工项
        → 人工全部通过 → 最终 diff 重审与门禁复核 → 本地 Commit
```

### 10.1 已接受的风险/限制

| 风险 | 本次处理边界 |
| --- | --- |
| SQLite/WAL 在 iCloud 副本中的一致性 | 保留现结构；只验证顺序操作；不声称换语言解决多机并发 |

| macOS 13/Intel 可能无实机 | 双架构构建 + 用户两台实测；显式列未实测项，不额外阻塞 |

| 补偿链在首个失败处停止 | `internal/anchor/journal.go` 的 `rollback` 遇到第一个补偿错误即 `break`，其余步骤标为 `not attempted` 并在错误中逐项列出。这是有意的：继续执行依赖已失败前置状态的破坏性步骤更危险。代价是极端情况下需要人工按错误列出的“未执行步骤”继续处理，不能假定机器已回到初始状态 |
| journal 记录与补偿动作的时序 | 破坏性操作在真正执行前先写入 undo 记录，因此进程被杀可能留下“记录了但未执行”的多余撤销项；补偿本身按身份校验执行，误删已被替换对象的窗口见下一行 |
| 进程/系统崩溃和断电 | 不在本次保障与验收范围，不能暗示已有保障 |
| 同权限进程并发替换目录 | 用户于实施复审阶段选择常规并发防护：使用随机暂存名、固定目录句柄和身份校验，保留正常目录操作；目录创建后、首次取得身份之前的极短窗口无法证明身份，同权限进程恰好替换时可能写入或误删替换对象。隔离与核验也不是按 inode 原子删除，不保证抵御持续对抗性替换。 |
| 严格 parser/表格/终端兼容成本 | 先 golden 和差分，禁止套用框架默认行为后降低要求 |
| 新 SQLite 驱动行为不同 | 先旧库双向、WAL/锁与只读测试；失败则修复/提问，不能改旧 schema 蒙混 |
| 旧恢复备份和强制覆盖有破坏性 | 保留经确认的成功语义，仅以普通错误补偿保护中间状态；全部验收使用可丢弃数据 |

### 10.4 后续 Harness 的证据格式

每项至少记录：ID、对应需求/差异、待测 commit、平台/工具链、命令或人工步骤、预期、实际、退出码或用户反馈、日志/摘要、结果、未覆盖项与最后复核时间。人工项不得填写虚构命令输出。

最终报告必须区分：构建成功、隔离自动测试通过、真实 Homebrew 通过、双机同步通过和未实测平台。只有自动项、约定人工项及最终审查全部通过时，才可宣告本任务完成。
